# قَصّة — دراسة سير عمل صانع المحتوى

تاريخ الدراسة: 2026-10-29، بتوقيت الرياض. النطاق: بحث فقط؛ لا تعديلات على المحرر أو الخادم، ولا على Resolve أو وسائط المستخدم.

## القرار المقترح

بعد دفعة إدارة المشاريع، أفضل ثلاث إضافات هي: **نقاط رجوع محفوظة، معاينة المصدر واختيار الجزء قبل إضافته، وتصدير مرتبط بنسخة محددة مع فحص جاهزية**. أوصي بهذا الترتيب؛ الأولى تحمي الثقة في تحرير AI، والثانية تختصر العمل اليومي، والثالثة تمنع التباس النسخ عند التسليم.

هذه توصية تصميم مستندة إلى شيفرة قَصّة ووثائق Blackmagic الرسمية، وليست نتيجة تفكيك سلوك Resolve. استُخدم REA المحلي فعلًا: فشل داخل sandbox، ثم نجح فحص هوية الملف خارجها، دون تشغيل التطبيق. لا توجد في هذه الدراسة ملاحظة تشغيلية لواجهة CapCut أو Resolve، ولا ادعاء بقياس سرعة المستخدم أو جودة الصادرات.

## ما الذي تحقق فعليًا؟

### 1. REA موجود محليًا، لكنه غير متصل بهذه الجلسة

تم العثور على الحزمة التالية في ذاكرة npm، دون تنزيل أو تثبيت جديد:

```text
C:\Users\waseem42\AppData\Local\npm-cache\_npx\a1722018f28f9df2\node_modules\rea-agents
package.json: name=rea-agents, version=6.7.0
repository: git+https://github.com/morluto/rea.git
launcher: scripts/rea.mjs
bundled skill: skills/reverse-engineer-anything/SKILL.md
skill metadata: version=42, tool_count=207
skill SHA256: FBCD39D6ABE803CF7AA49C1880815BC8E22BA2AF87A23681944F687BB7629EB1
node --version: v24.18.0
```

قرأت المهارة المرفقة ودليل الاتصال، واستخدمت المشغّل العام للحزمة. لم تظهر أدوات REA ضمن الأدوات المتصلة؛ لذلك استُخدم CLI. بحث المسارات اقتصر على أسماء الملفات والحزم والمهارات ذات الصلة؛ لم تُفتح ملفات اعتماد أو مفاتيح. فحص التسجيل أدناه قرأ حالة الإعدادات بواسطة REA، دون طباعة محتوياتها الخام.

الأوامر المنفذة، حيث `$taskRea` يشير إلى `scripts/rea.mjs` أعلاه:

```powershell
node $taskRea --help
node $taskRea inspect --help
node $taskRea observe-native-ui --help
node $taskRea inspect-artifact --help
node $taskRea doctor --client codex --json
node $taskRea inspect-artifact 'C:\Program Files\Blackmagic Design\DaVinci Resolve\Resolve.exe' --format json
## أُعيد الأمر السابق خارج sandbox، ثم نُفذ فحص ترويسة محدود:
node $taskRea inspect-managed-artifact 'C:\Program Files\Blackmagic Design\DaVinci Resolve\Resolve.exe' --format json
```

نتائج التشخيص المؤكدة من خرج REA:

| الفحص | النتيجة | حدود الاستنتاج |
|---|---|---|
| Node | healthy، 24.18.0 | متوافق مع الحزمة المحلية وفق تشخيصها؛ لا يعني جاهزية كل محرك |
| تسجيل Codex | `config_drift`؛ تسجيل REA مفقود حسب doctor | لا يثبت اتصال جلسة حية؛ الأدوات غائبة بالفعل من هذه الجلسة |
| Claude Code ضمن المعلومات الإضافية | registration state=`missing` | لم يُنفذ تشخيص مستقل لـ Claude؛ لا يمكن الجزم بأنه استُخدم سابقًا أو لم يُستخدم |
| هوية المهارة المثبتة للعميل | `missing` | المهارة المرفقة داخل حزمة npm موجودة وقرئت؛ هذان نطاقان مختلفان |
| Hopper، Ghidra، IDA، Kuna | غير مهيأة/غير متاحة حسب الفحص | لا يكفي وجود الحزمة لفتح تحليل native عميق |
| اختبار REA Windows native، ضمن فحص JADX | `Read final handle path failed … (Win32 5): Access is denied` في مجلد sandbox المؤقت | قيد بيئة في هذا الفحص؛ لا يثبت عطل تثبيت Java أو Resolve |

لم أغيّر تسجيل MCP أو صلاحياته، ولم أثبّت محرك تحليل. النسخة upstream المفتوحة أثناء البحث تصف إمكانات أحدث؛ اعتمدت في الأوامر على مساعدة **6.7.0 المحلية**، لا على افتراض تكافؤ الإصدارين. المصدر الرسمي: [morluto/rea](https://github.com/morluto/rea).

### 2. فحص Resolve نجح في الهوية، ولم يصل إلى سلوك الميزات

ملف التطبيق المثبت، وفق بيانات الملف المقروءة بأداة PowerShell العادية:

```text
C:\Program Files\Blackmagic Design\DaVinci Resolve\Resolve.exe
ProductVersion: 21.0.0.47
Length: 579935160 bytes
```

هذا رقم إصدار الملف، وليس تحققًا من رخصة Studio أو النسخة العاملة. `D:\DaVinci Resolve` مجلد عمل للمستخدم، وليس مجلد تثبيت التطبيق. مجلد `D:\AntigravityProjects\davinci-resolve-mcp` يحوي تكاملًا ووثائق API، ولا يثبت أنه متصل بتطبيق عامل.

أعاد أمر REA `inspect-artifact`:

```text
code: access_denied
category: unavailable
retryable: false
boundary: filesystem-read
EPERM: operation not permitted, realpath
'C:\Program Files\Blackmagic Design\DaVinci Resolve\Resolve.exe'
```

الخرج الخام للمحاولة الأولى محفوظ في [rea-resolve-artifact.json](./rea-resolve-artifact.json). هذا **سجل فشل داخل sandbox**؛ لا يصح تعميمه على التثبيت كله. خروج مشغّل الأمر برمز 0 لا يغيّر حقيقة وجود خطأ داخل JSON.

أُعيد الفحص المحدود نفسه عبر `exec_command` بصلاحية `require_escalated`، بعد طلب صريح بإعادة المحاولة المصرح بها. نجح، والخرج الكامل في [rea-resolve-artifact-unsandboxed.json](./rea-resolve-artifact-unsandboxed.json):

```text
Evidence: ev_22c9196f35b459c5e27e0a03f16033bf11e884be2dbe885c174945b7567ac089
Inventory evidence: ev_4186733bc683cfa973d796bdd00c2c782447fa25f20608f1ae2241a6cdf7159b
Provider: rea-artifact-graph v1 (REA safe artifact graph provider)
Format: pe
SHA256: 4f3a637aadb6817d3cb5afa2ebcb97d646af8fd67e8b262acda26ff06acfa91e
Size: 579935160 bytes
Graph: 1 node, 1 occurrence, 0 edges
Coverage: complete-within-substeps; inventory_artifact completed
```

هذه هوية artifact مرصودة فقط. تقرير REA نفسه يقول إن inventory bytes لا تميز managed من native، وأن الفحص لا ينفذ الملف ولا يثبت الدلالات الخاصة بالصيغة. لا يثبت جرد عقدة واحدة أن التطبيق كاملًا بلا مكونات أخرى؛ الهدف المحدد كان `Resolve.exe` فقط.

اتبعت اقتراحه بفحص ترويسة `inspect-managed-artifact` دون تحميل كود الهدف أو تفكيكه. توقفت المحاولة عند `resource_constraint` / `memory`، لأن حد snapshot هو `134217728` بايت (128 MiB) والملف أكبر منه. [الخرج الخام](./rea-resolve-managed-header.json). لم أرفع الحد أو أثبّت محللًا؛ معرفة لغة تنفيذ Resolve ليست لازمة للمقارنة الوظيفية هنا. لم تُفتح جلسة تحليل native تحتاج إغلاقًا.

لم يُرجع `Get-Process -Name Resolve,CapCut -ErrorAction SilentlyContinue` عملية مطابقة في لحظة الفحص. لذلك لم أستخدم `observe-native-ui` على PID مفترض، ولم أشغّل التطبيق أو أفتح مشروعًا للمستخدم. لم يُعثر على مجلد CapCut في المسار الشائع `AppData\Local\CapCut`؛ هذا بحث محدود لا يثبت غيابه عن الجهاز كله.

### 3. البديل الذي استُخدم

تمت المقارنة من:

- الشيفرة المحلية لقَصّة: المكونات، مخطط البيانات، العمليات، التخزين، الوظائف، ومسار الرندر؛ فحص قراءة، لا اختبار تشغيل.
- صفحات Blackmagic الرسمية للـ Edit والـ Media، ودليل إدارة مكتبات Blackmagic Cloud.
- ملف API المرفق بتكامل Resolve المحلي، رأسه `Last Updated: 5 May 2026`؛ يؤكد واجهات معلنة مثل `DuplicateTimeline` و`ExportProject`، ولم تُنفّذ هذه الواجهات.

لم تُستخرج أصول محمية، أو يُنسخ كود التطبيق المرجعي، أو تُجر مسوح تفكيك واسعة. تعذّر جلب دليل المبتدئ الرسمي PDF عبر أداة الويب بسبب حجمه؛ لا تعتمد التوصيات على محتوى لم أقرأه.

## مواصفات أفضل ثلاث إضافات

### 1. نقطة رجوع قبل الدفعة

واجهة داخل المحرر: «احفظ نقطة رجوع»، اسم اختياري، تاريخ، صاحب التعديل، وعدد اللقطات/المدة. ينشئ المساعد نقطة تلقائية قبل دفعة واسعة، مع سياسة احتفاظ محدودة. عند الاستعادة، تُحفظ نقطة للحالة الحالية أولًا، ويُعرض فرق موجز؛ الاستعادة نفسها تعديل قابل للتراجع وفق عقد العمليات.

أصغر تنفيذ مفيد: snapshot محفوظ من Project في مسار داخلي غير قابل لاختيار مسار عشوائي، ومعه revision ودلالات إصدار schema. الكتابة تتم إلى ملف مؤقت ثم استبدال آمن؛ لا تعتمد على نجاح `writeFileSync` بوصفه ضمانًا ضد انقطاع العملية. لا حاجة لنسخ فيديوهات المصدر لكل نقطة.

لكن snapshot JSON وحده ليس نسخة احتياطية كاملة: قد تتغير HTML graphics أو LUTs في المسارات نفسها، وقد تكون بعض الوسائط مراجع خارجية. أضف manifest بهويات الاعتماديات وتحقق منها؛ أصول الرسوم المعدلة تحتاج إصدارًا ثابتًا أو نسخة صغيرة. وضّح عند تعذر استعادة المظهر المطابق، ولا تصف نقطة تحرير بأنها أرشيف مستقل قابل للنقل.

أماكن العمل: `packages/server/src/store.ts`، عمليات الاستعادة في shared، لوحة history/MCP؛ لا يحتاج تغيير محرك الرندر. احفظ مراجع ملفات التحليل المتصلة بالحالة، ولا تمسح وسائط أُضيفت لاحقًا من القرص عند استعادة حالة أقدم.

معيار قبول: نقطة تبقى بعد إعادة تشغيل الخادم؛ استعادة لا تكتب فوق الحالة الحالية دون نقطة رجوع؛ رفض نقطة غير صالحة أو اعتماد مفقود برسالة مفهومة؛ دفعة واحدة للتراجع؛ لا حذف للمصدر؛ اختبارات انقطاع كتابة وتزامن تعديلين. هذا العمل غير منفذ في الدراسة.

### 2. افتح المصدر، ثم أضف الجزء

النقر على ملف يفتح معاينة مصدر مستقلة بحالة تشغيل لا تغيّر playhead المشروع. أزرار بداية/نهاية ومدة الجزء المختار؛ I/O من تعريف الاختصارات المركزي وبحسب سياق التركيز. «أضف عند المؤشر» لـ B-roll، و«أضف إلى القصة» لـ V1. استخدم البروكسي عند توفره، مع الحفاظ على توقيت المصدر. أضف خيارًا صريحًا «استيراد للمكتبة فقط» للمصادر؛ حافظ على السلوك التلقائي الحالي كخيار مفهوم.

أصغر تنفيذ: إعادة استخدام عنصر فيديو و`add_clip` مع `in/out` الصحيحين. اختيار النطاق حالة UI مؤقتة؛ لا عملية جديدة ما دام التعديل الفعلي يستخدم العملية الموجودة. تعديل سلوك الاستيراد الاختياري يحتاج API/MCP واضحًا، لا تجاوزًا لـ Store. لا تبدأ بـ Smart Bins أو مشغل ثانٍ دائم على شاشة ضيقة.

أماكن العمل: `MediaPanel.tsx` ومكون معاينة مصدر، `keys.ts`؛ وسيط import اختياري في server/MCP. يجب أن يحترم V1 المغناطيسي وألا يحوّل ثواني المصدر إلى ثواني تايملاين خطأ.

معيار قبول: اختيار 12–17 ثانية يضيف هذا الجزء، لا أول خمس ثوانٍ؛ صوت المصدر لا يعمل مع معاينة المشروع؛ إضافة ثانية من المصدر نفسه مسموحة؛ فيديو بلا بروكسي يعمل؛ الصور لها مدة عرض؛ RTL وأحجام الشاشة الضيقة مفهومة. لا حاجة لاختبار يكرر JSX؛ الاختبارات المهمة للتحويل والإضافة وحالة التشغيل.

### 3. تسليم معروف النسخة

ابدأ ببطاقة جاهزية في حوار التصدير: ملفات مفقودة، تعليقات مفتوحة، اقتراحات لم تُراجع، مشاكل قص من `check-cuts`، ومواصفات الناتج. اجعل الملفات المفقودة مانعًا واضحًا، والملاحظات التحريرية تحذيرات قابلة للتجاوز؛ لا تمنع صاحب المشروع من التصدير بسبب اقتراح اختار تركه.

بعدها احفظ وصفة تسليم صغيرة باسم واضح (الجودة، المقاس، الدقة، FPS، اسم ملف). اربطها بمراجعة Project مجمّدة عند تقديم الطلب، لا عند حصول الوظيفة على دورها. مجرد حفظ رقم `rev` داخل الذاكرة لا يكفي لأنه يعود للصفر بعد إعادة التحميل؛ استخدم هوية snapshot دائمة أو hash للحالة مع manifest للأصول.

احفظ سجل نتيجة: نسخة الإدخال، الوصفة، المسار النهائي، الحالة، الوقت، وبيانات فحص ffprobe للناتج. غيّر اسم الناتج لكل طلب حتى لا يصبح رابط «آخر فيديو» اسمًا واحدًا يتبدل محتواه دون وضوح. لا تتطلب هذه البداية رفعًا إلى حسابات اجتماعية أو تغيير aspect المشروع في الخلفية لإنتاج نسخة أخرى.

أماكن العمل: `Header.tsx`، مسار `/render` في server، `jobs.ts`، وبيانات الإدخال إلى compile. إعادة الاستخدام: تقرير القص موجود، وطابور الوظائف والكاش موجودان. لا تدّع أن «الوظيفة اكتملت» تحقق بصري؛ اختبر عينات مقصودة وقارن أبعاد/مدة/مسارات الصوت بالناتج.

معيار قبول: طلب رندر ثم تعديل المشروع أثناء انتظار دوره لا يغيّر ناتج الطلب السابق؛ تحديث الواجهة يعرض نسخته الصحيحة؛ سجل النتائج يبقى بعد restart؛ وظيفة كانت تعمل عند الانقطاع تُوسم interrupted بدل ادعاء استئنافها تلقائيًا؛ لا كتابة فوق ملف ناجح آخر؛ فحص ملفات مفقودة قبل بدء الرندر.

## ما الذي يمكن أن يغيّر التوصية؟

- إذا كان المستخدم يعمل دائمًا بمصدر واحد وB-roll قليل، تصبح **تصحيحات التفريغ والبحث** أهم من معاينة المصدر؛ اختبر ذلك على جلسة فعلية قبل تنفيذ #2.
- إذا كان الرندر يبدأ فورًا ولا يوجد تعديل أثناءه، يقل تكرار خطر الطابور؛ يظل تثبيت النسخة والسجل مفيدين، لكن قد تتقدم تصحيحات النص على الوصفات.
- إذا كانت خسارة العمل غير شائعة، لا يعني ذلك انتفاء الحاجة لنقاط الرجوع؛ فائدتها الأساسية أيضًا المقارنة وتجربة تحرير AI، لا التعافي من الأعطال فقط.
- نقاط رجوع كبيرة بلا سياسة احتفاظ، أو تعهد بحفظ الأصول دون تنفيذ، قد يضيفان ثقة زائفة. عالج حدود الاستعادة قبل عرض زرها كضمان.

## حالة أسئلة البحث والتسليم

| السؤال | الحالة |
|---|---|
| هل REA موجود؟ وأي إصدار/تعليمات؟ | أُجيب: حزمة cache 6.7.0 ومهارة مرفقة 42 |
| هل فحص Resolve نجح؟ | جزئيًا: فحص هوية artifact نجح خارج sandbox وله Evidence ID؛ فحص managed توقف عند حد الذاكرة؛ تحليل السلوك لم يتحقق |
| هل شاهدنا تنفيذ واجهة المنافس؟ | لم يتحقق؛ لا تطبيق مطابق عامل وقت الفحص، ولم يُشغّل تطبيق |
| ما الذي لدى قَصّة فعلًا؟ | جرد من المصدر، مع حفظ بصمات ومقتطفات؛ دون اختبار runtime في هذه الغرفة |
| ما أفضل خطوات قابلة للبناء بعد الرئيسية؟ | توصيات 1–3 أعلاه، محددة النطاق ومعايير القبول |
| هل نُفذت هذه التحسينات أو قيس أثرها؟ | لا؛ هذا مستند بحث. تنفيذ دفعة إدارة المشاريع منفصل ويُتحقق منه في المحادثة الرئيسية |

الملفات الناتجة عن هذه الدراسة فقط: هذا المستند، ثلاثة سجلات REA الخام (فشل sandbox، فحص الهوية الناجح، وحد الذاكرة)، ولقطة أدلة المصدر. لا توجد تغييرات تطبيقية من غرفة البحث.
